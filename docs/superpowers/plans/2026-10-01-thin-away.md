## Task 2 — the denial contract

`hooks/guard.py`
- `emit_permreq(behavior, message=None)`: adds `decision.message` when given; never `interrupt`.
- `denial_kind(cmd)`: walks `segments()` with `command_word()`; returns `"push"` if any segment is
  `git … push` (skip git global opts as `git_calls` does today), else `"delete"` if any word is in
  `DELETE_BINS | {"rmdir"}`, else `"other"`.
- `DENY_MESSAGES` dict for the three kinds, worded per spec Section 1, each ending with
  `note_suffix(session)`.
- `handle_permissionrequest`: ExitPlanMode stays allow; every other tool → log `deferred` (as today)
  and `emit_permreq("deny", message)`; non-Bash tools use `"other"`.
- `handle_permissiondenied(hook)`: when away is on, log `auto_denied` with tool and input; emit
  nothing.
- `block_streak(session)`: from `tail_lines(EVENTS, 800)` for this session since the absence began,
  count total `deferred` + `auto_denied`, and the trailing run of them not broken by another
  tool-call event. `degraded(session)` = streak ≥ 3 or total ≥ 20. When degraded, the deny message
  and the Stop ping text append the degraded line from the spec.
- `handle_stop`: add `auto_denied` to the events that count as a denial.
- `main()`: route `permissiondenied`.

`hooks/guard.sh`: `permissiondenied` gets `FAILSAFE=0` and always starts python when armed.

Tests (`tests/policy_cases.py`, new `permission_prompt_cases` replacing the stashed one)
- Messages for `git push -u origin x`, `cd x && git push`, `git -C r push`, `FOO=1 rm x`,
  `rmdir d`, `make deploy`, tool `WebFetch`; `interrupt` absent in every output.
- ExitPlanMode via PermissionRequest → allow.
- `permissiondenied` logs `auto_denied`; output empty.
- Seed 3 `auto_denied` events → next deny message carries the degraded line; 2 → it does not.
- Away off → `permissionrequest` and `permissiondenied` emit nothing.

Commit: "Deny prompts with a message the agent can act on, and count auto-mode blocks"

## Task 4 — `away perms`

`bin/perms.py` (new, stdlib only)
- `SOURCES`: ordered list of (label, path): managed `~/.claude/remote-settings.json`,
  `/Library/Application Support/ClaudeCode/managed-settings.json`,
  `/etc/claude-code/managed-settings.json`; user `$CLAUDE_CONFIG_DIR/settings.json`,
  `settings.local.json`; project `<cwd>/.claude/settings.json`, `.claude/settings.local.json`.
  Missing or unreadable files skipped silently.
- `rules()` → list of (kind ask|deny, rule, source label).
- `matches(rule, segment)`: Bash rules only. `Bash(x:*)` → prefix `x`; `Bash(x)` with `*` →
  `fnmatch` on the whole segment; without `*` → exact. Non-Bash rules print in the listing but are
  never matched against a command.
- `verdict(cmd)`: split with `shlex`-aware splitting on `&&`, `||`, `;`, `|` (copy guard's
  `segments` logic, ~20 lines, rather than importing guard). Deny beats ask across segments.
- CLI: no args → listing grouped by source, each line `denied while away  <kind>  <rule>`; with a
  command → one verdict line per segment plus "best effort: the harness has the final word". Never
  the word "allowed".
- `bin/away`: `perms) shift; "$PY" "$AWAY_HOME/bin/perms.py" "$@" ;;`, plus help line; add to the
  no-update-check fast list.
- `guard.py` `handle_userpromptsubmit`: when injecting full rules, append the output of
  `perms.py --brief` (ask/deny rules, one per line, deduped, capped at 60 lines) via `run()`,
  wrapped in try so a failure only drops the list.
- `setup.py` `audit_payload`: add `bin/perms.py`.

Tests: `tests/perms_cases.py` with a sandboxed `HOME` and `CLAUDE_CONFIG_DIR` holding a managed
file with `ask: Bash(git push*)`, `deny: Bash(rm -rf *)`, and a project file with
`deny: Bash(make deploy:*)`. Cases: listing shows all three with sources; `git push -u origin x`
→ asks; `cd x && rm -rf build` → denied by `Bash(rm -rf *)`; `make deploy prod` → denied (project);
`ls` → no rule matched; output never contains "allowed". Managed paths are injectable via
`AWAY_PERMS_MANAGED` (colon-separated) so the test never reads `/Library`. Add to `run_all.sh`.
